# Mobile design research: what was and was not done

The directive asked for design research through Mobbin. Mobbin was described as connected, but no Mobbin tools were available in this session and a direct web request was refused (403). It was not circumvented. So **no Mobbin research informs the current design**, and this document does not pretend otherwise.

What the app's design is based on instead:
- The directive's own palette and rules (#080B0A / #0E1311 / #151B18 background tiers, #38E078 as a restrained accent, #F3F7F4 / #97A39C text), five-item bottom navigation, three-screen onboarding.
- The Viro operator and organization consoles built earlier in this project (section eyebrows, list rows instead of cards, status words with a coloured dot, evidence labels).
- Plain-language rules: every finding shows its evidence type (MEASURED, TESTED, INFERRED); missing data says "Not available on this device"; no invented percentages or predictions.

Seen on a real screen (TECNO CI6): large-title screens read well; the Android overlay on the left edge of the screenshots is the phone's own floating tool, not the app. Still to judge by a person: touch-target comfort, one-handed reach, dark-room legibility, and whether the Home screen feels like a security system rather than a generic dashboard.

If Mobbin becomes available, the useful references are: onboarding for device-health and security apps, pairing/connection flows (code entry, success state), scan-in-progress states, and empty/offline states. Use them for patterns only; nothing should be copied.
